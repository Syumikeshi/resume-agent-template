# 踩坑清单 —— 付出过代价的技术规则

> 每一条都是真实踩过的坑。改简历/改文档前扫一眼，能省一轮返工。
> Agent 执行层面的浓缩版在 AGENTS.md §6。

## LaTeX / 简历

1. **Carlito + XeTeX 会让 PDF 文本层丢数字**——视觉完全正常，但 `pdftotext` 提取不到。
   遇到文本层异常时在导言区加 `\XeTeXgenerateactualtext=1`。
2. **中文版简历比英文版「吃」版面**（CJK 字符宽 + 不支持字母间距压缩）。
   任何改动后**逐份**量页数，不能只看英文版。
3. **行尾断字**：完全禁用断字（`\hyphenpenalty=10000`）可能导致 Overfull hbox；
   模板里的组合（禁断字 + `\emergencystretch`）是调过的，别单独动一项。
4. **字体平台差异**：cls 里有回退链（Avenir Next → Helvetica Neue → TeX Gyre Heros；
   中文 PingFang SC → ctex 平台默认）。换了字体**必须重新量页数**——字宽不同，版面会变。
5. **PDF 元数据会泄露旧信息**：`\hypersetup` 里的 pdftitle/pdfauthor 每次改名/改方向都要同步，
   交出去的 PDF 元数据里出现旧姓名或乱码很难看。
6. **黑白版是派生物**：`*-bw.tex` 由 `make_bw.py` 生成，永远不要手改它——改彩色版后重新生成。

## 数据一致性

7. **同一个数字常在文中出现三处**（指标卡 / 正文结论 / 表名）。改任何数字前先全文检索它。
8. **事实性修正不会自动传播。** 确认一处口径变化（GPA、毕业时间、任职时长）后，
   必须按依赖图排查所有引用它的交付物——简历、清单、熟悉记录、作品集。
9. **「待核实」是合法状态。** 薪资、WLB、截止日期拿不准就标待核实并进追踪表，
   别用一个看似干净的猜测值。

## 流程 / 协作

10. **改产物不改源 = 白改。** docx/xlsx/PDF 上能改的事，回到源（md/清单/tex）改然后重建，
    否则下次重建全部退回。
11. **xlsx 手填数据要防丢。** `build.py` 默认增量更新：按「表名+企业名」沿用旧表的
    投递日期/进展，招聘会现场记录整表保留；只有 `--rebuild` 才全量重做。
    结构性内容（企业/梯队/薪资/备注）仍以清单为准，重跑会被清单覆盖。
12. **会话日志只在结尾追加。** 试图「整理」历史日志的那次提交，差点丢了决策理由——历史就是历史。
13. **新会话交接只依赖 MEMORY.md。** 哪怕日志写得再好，Agent 冷启动也只应读一份快照；
    快照里没有的信息等于丢失，所以要维护快照而不是攒日志。

## Excel / 脚本

14. **openpyxl 写公式不如写值。** 公式依赖 Excel 引擎重算，跨平台打开有风险；
    追踪表全部直写值 + 条件格式（格式是显示层的，安全）。
15. **下拉列表字符串里的引号**：`DataValidation(formula1='"A,B,C"')` 整串是一个字符串，
    里面的值不能含逗号（会被当成分隔符）。
