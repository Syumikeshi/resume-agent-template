# tracker/ —— 投递清单 → 追踪表流水线

把「找哪些公司、投哪个方向」的决策写成**清单**（markdown），再由脚本自动生成
带下拉、着色、筛选的 **xlsx 追踪表**。清单是唯一真相源，追踪表是派生物。

## 流程

```bash
cd tracker
python3 extract_tracker_data.py   # lists/*.md  → tracker_data.py（自动生成，勿手改）
python3 build.py                  # 增量更新：tracker_data.py → 追踪表.xlsx
python3 build.py --rebuild        # 全量重做：忽略旧表，从清单完全重建（需要时才用）
```

依赖：Python 3.9+，openpyxl（缺了会自动 pip 安装）。

## 清单怎么写

- 一份清单一个 `.md` 文件，放 `lists/` 下；`# 一级标题` = 方向名（也是工作表名）
- `### 三级标题` = 梯队（第一梯队 / 第二梯队 / 第三梯队 / 需确认 / 建议放弃）
- 表格首列为 `企业`（也兼容 `机构`、`类别 | 企业` 两列式）
- 列名建议：`企业 | WLB | 岗位方向 | 地点 | 薪资 | 备注`（薪资可带「待核实」）
- 示例见 `lists/data-analytics.md`（**示例里的公司与数据均为虚构**）

## 追踪表结构

- **招聘会现场记录**（空白模板）：招聘会当天随手记，带「前台/中后台」「有无业绩指标」下拉
- **每个方向一张表**，统一十列：序号 / 优先级 / 企业 / WLB / 岗位方向 / 地点 /
  薪资（含核实状态）/ 投递日期 / 进展 / 备注
  - 「进展」是下拉：待投递 → 已投递 → 已笔试 → 面试中 → 已录用 / 已拒绝 / 无回复
  - 梯队与进展都有条件格式着色，打开即可视化

## 使用纪律

1. **增量更新是默认行为**：重跑 `build.py` 会按「工作表名 + 企业名」沿用旧表的
   **投递日期** 与 **进展** 两列，招聘会现场记录整表保留（行数不够自动扩展）——
   改完清单重跑两个脚本，手填的过程数据不会丢
2. **结构性内容以清单为准**：企业 / 梯队 / 薪资 / 备注等来自清单，重跑会被清单覆盖——
   要改这些，改 `lists/*.md` 再重跑，不要在 xlsx 里改
3. **全量重做**：`python3 build.py --rebuild` 忽略旧表过程数据，从清单完全重建
4. 清单里删掉的方向，其工作表（含过程数据）会在下次重跑时移除并提示——删清单前想清楚
